1. What is Vigía

Vigía is a Markdown viewer and editor for Windows. You format text with buttons — headings, bold, lists, tables, code — and Vigía writes the Markdown tags behind the scenes. Every document is shown exactly the way GitHub displays it, in light or dark theme.

It is designed for README.md files, notes, documentation and any .md file you want to read or edit without memorising syntax.

2. Installation

Run Vigia-Setup-3.6.0.exe. The installer is available in English, Spanish and Japanese and does not need administrator rights: it installs for the current user in %LOCALAPPDATA%\Programs\Vigia.

OptionWhat it does
Create a desktop shortcutAdds a Vigía icon to the desktop.
Open .md files with VigíaAdds Vigía to Open with for .md / .markdown files, and makes it the handler for those files for the current user.
Add "Open with Vigía" to folders in ExplorerRight-click a folder (or the empty space inside one) in Explorer to open it in the Files panel. In Windows 11 it is under Show more options.

Requirements: Windows 10 or 11 (64-bit) and Microsoft Edge WebView2 Runtime, which is already part of Windows 11. The .NET runtime is included; nothing else has to be installed.

Up to version 1.1.1 the program was called Quillforge, and up to 2.2.1 Gryphmark. If one of them is installed, the installer removes it, and Vigía copies its settings, recent files and recovery drafts on the first start.

To uninstall: Settings → Apps → Installed apps → Vigía → Uninstall. Your settings in %APPDATA%\Vigia are kept.

4. Three ways to see a document

Switch with the three buttons at the right end of the toolbar — Visual · Markdown · GitHub —, the View menu or the shortcuts. Hover over a button to see what it does.

ButtonShortcutWhat you see
Visual
Visual editor		Ctrl+1The formatted document. Type and use the buttons; the Markdown is generated for you.
Markdown
Markdown source		Ctrl+2The raw Markdown on the left and a live preview on the right. For when you want to see or touch the tags.
GitHub
GitHub preview		Ctrl+3Read-only page rendered like GitHub, with syntax highlighting, task lists and clickable links.

Read only

When you only want to read a document, choose Read only in the Edit | Read only switch, to the left of the view buttons (also View → Read only or Ctrl+Shift+L). The text is locked in every view: keys, paste, drag and drop and the task boxes do nothing, and the formatting buttons are greyed out. You can still read, select, copy, find and switch views. If you type, the status bar reminds you how to unlock it. Choose Edit to write again; Vigía remembers your choice.

5. Tabs

Vigía keeps several documents in one window, one per tab, in the strip above the text. Each tab has its own editor: it keeps its undo history, cursor and scroll position while you look at another one. A dot on a tab marks unsaved changes; the title bar and the status bar show the document of the tab you are on, and the outline follows it.

ActionHow
Open a file in a tabAny way of opening a file: a click in the Files panel, a favourite, File → Open… (pick several files at once to get a tab each), Open recent, a search result, a .md link, a file dropped on the window or opened from Explorer. A file already open is not opened twice: its tab is shown. A new tab goes next to the one you are on; an empty untitled tab (or the sample, untouched) is used instead of adding another.
Preview tabA click on a file in the Files panel (or in Favourites or Recent) shows it in a passing tab, its name in italics: the next file you click there takes its place, so browsing a folder does not leave a tab per file. The tab stays as an ordinary one as soon as you type in it, or with a double click on the file or on the tab. Files opened any other way get an ordinary tab. File → Preview tab for files from the panel turns this off (on by default).
New tabCtrl+N, File → New tab or the + at the right end of the strip: an untitled document.
SwitchClick a tab, or Ctrl+Tab / Ctrl+Shift+Tab (also Ctrl+PageDown / Ctrl+PageUp). When they no longer fit, the mouse wheel over the strip scrolls it, and the ⌄ button lists them all.
CloseCtrl+W, File → Close tab, the × of the tab or a middle click on it. A tab with unsaved changes asks first (with autosave on, a file with a name is just saved). Closing the last tab leaves an empty untitled document. Ctrl+Shift+T (File → Reopen closed tab) brings back the last one closed.
MoveDrag a tab along the strip.
Right-click a tabClose tab, Close the other tabs, Close the tabs to the right, Close all tabs, Reopen closed tab, Copy path, Show in folder and Reopen tabs at start.

Closing the window closes every tab; each one with unsaved changes is shown and asked about in turn, and Cancel keeps the window open. To find them again next time, turn on File → Reopen tabs at start (off by default): the next start opens the same files, in the same order, with the same tab shown. The list is kept as the tabs change, so it also survives a crash or a power cut. Untitled documents are not kept, and a file that no longer exists is left out. Each dedicated instance keeps its own tabs; an extra window (File → New window) never writes over the main window's.

View settings are the same for every tab: mode, read only, text width, spell check, theme, language and zoom. A tab you are not looking at takes a change when you show it again. If another program changes the file of a hidden tab, the tab reloads it (or asks, if it has unsaved changes) when you show it. Renaming or moving a file from the Files panel takes its tab along.

6. Folders: the Files panel

Like VS Code or Obsidian, Vigía shows folders as trees on the left: subfolders and Markdown files (.md, .markdown). You can have several folders open at once; each one is a block with its own pastel colour and a stripe on its left edge, so you see at a glance where one tree ends and the next begins. Click a file and it opens beside the trees.

ActionHow
Open a folderThe + button of the panel, File → Open folder…, the Open folder… button of the empty panel, dropping a folder on the window, or right-clicking a folder in Explorer → Open with Vigía (installer option; in Windows 11 it is under Show more options). Each new folder is added below the others. To close one, right-click its title → Close this folder; File → Close all folders empties the panel (nothing is deleted from the disk).
Show / hide the panelCtrl+Shift+E, the folder button of the toolbar (the third), or View → Files panel. It shares the sidebar with the outline: the files above, the outline below. Drag the right edge of the sidebar to make it wider, and the line between the two to change their heights; both are kept. Each dedicated instance keeps its own layout.
LayoutThe layout button at the right end of the toolbar is a small drawing of the current layout. A click opens a panel with the six layouts drawn: Files and Outline on the left (one above the other, or side by side), one on each side of the text (either way round), or both on the right. A click on a drawing applies it at once; below them, Files, Outline and Search turn each pane on or off and Swap Files and Outline trades their places. View → Layout has the same choices, and Choose a layout visually… at its end opens the same panel. Each layout keeps its own sidebar width: drag the edge of a sidebar and that layout remembers it.
You can also drag a pane by its title (FILES, CONTENTS or SEARCH) to an edge of the window: while you drag, both edges are outlined and the place the pane would take is filled in, with its name (Outline on the right, Files below Outline…). Near the other pane, its upper part puts the dragged one above it, the lower part below, the middle beside it. Let go to move it; let go in the middle of the window, or press Esc, to leave everything as it was.
BrowseClick a folder to open or close it; click a file to open it. Enter does the same on the selected row.
FavouritesEach file and folder row has a star at its right: faint when the pointer is over the row, filled and golden for a favourite. A click on it (or right-click → Add to favourites, or File → Favourite for the open file) adds the file to FAVOURITES, the first block of the panel: one list for every open folder, with each file's folder in grey. Favourite folders come first and open like a tree. Drag a favourite onto another one to reorder the list (or right-click → move up / down, or remove it); right-click the block's title to sort the list A → Z, remove the files and folders that no longer exist (the entry is greyed out while none is missing), or empty it (the files themselves are never touched). A favourite renamed or moved from the panel follows its file. A file opened from Favourites leaves the folder trees as they are: nothing opens or scrolls to it (opened from its folder, the tree follows it).
Search in the foldersView → Search in the folders, the magnifier of the toolbar or Ctrl+Shift+F shows the SEARCH pane. Type two letters or more: every Markdown file of the open folders (the files the trees show) is searched a moment after you stop typing. Results come grouped by file, each line with its number and the match in bold; a click opens the file at that very match, with the find bar showing it. Aa matches case. A search stops at 300 files or 5,000 matches (it says so: be more precise). It is a pane like the others: place it with the layout button or by dragging its title.
Recent filesOff by default. View → Recent files in the panel (or the panel's ⋯ menu) adds a RECENT block under the favourites with the last eight files opened.
Right-click a folder's titleNew Markdown file… and New folder…, Pin to top / Unpin, Close this folder, Colour (twelve pastel colours or Automatic), Move up / Move down (in opening order), open in a dedicated instance, desktop shortcut, show in folder, copy path, refresh.
New Markdown file, new folderThe first two buttons of the toolbar (a page and a folder with +), or right-click a folder → New Markdown file… / New folder…. They are made on disk at once, in the folder selected in the tree (or the folder of the selected file); with nothing selected, in Documents\Vigia, which is created and added to the panel the first time. A free name is offered (New document.md, New document 2.md…); a file without a Markdown extension gets .md and starts with its name as a heading. A new file opens at once; a new folder stays selected, so the next file goes into it. Nothing is ever written over: a name that is taken is refused. Both buttons work in every mode, also in the GitHub view and in read only, but only with the tree unlocked (the padlock at the top of the panel): locked, they and the menu entries are greyed out, and the pointer resting on one says so.
Right-click inside a treeOn a file: open, open in a new window, show in folder, copy path, and Convert to TXT, which writes a .txt next to it as the document reads in the GitHub view (headings, lists, tables and links in plain text) and leaves the Markdown file as it is. On a folder: new Markdown file, new folder, show in folder, copy path, refresh. On both: Rename (also F2) and Delete (also Del).
DeleteWith the tree unlocked (the padlock at the top of the panel; locked, Delete is greyed out and Del does nothing), right-click a file or folder → Delete, or select it and press Del. It goes to the Recycle Bin, where it can be restored (a folder with everything in it). A network folder or a USB stick has no Recycle Bin: there Vigía asks whether to delete it for good, every time. Vigía asks first; tick Don't ask again in this window and it stops asking until that window closes: a new window, or Vigía started again, asks again. The tabs of what is deleted close, and it leaves Favourites and Open recent. The open folders themselves (the coloured blocks) are not deleted from here: their menu closes them.
Panel buttonsThe two arrows undo and redo renames and moves; the padlock locks or unlocks the tree for dragging; + add folder, refresh, collapse all / expand all (one button: while any folder is open it collapses them all; when everything is closed it expands every folder, every level; its icon and tooltip say which; the ⋯ menu has both), and ⋯: the order, the colours and what opens at start. Expanding stops after 1,500 folders, so a tree as big as a whole drive does not freeze the window.

Renaming and moving files

Changes made from the tree happen on disk. F2 or right-click → Rename renames the selected file or folder. To move files and folders, click the padlock in the panel header to unlock the tree, then drag them onto a folder (or onto a file in that folder); the target folder is highlighted while you drag. Click the padlock again to lock the tree, so a slip of the mouse moves nothing. Each rename and move can be undone with the ← arrow of the header and redone with →, or with Ctrl+Z / Ctrl+Y while the tree has the focus; the arrow's tooltip says what it will undo or redo. If the open document is renamed or moved, it stays open at its new place, saved first if it had changes. The open folders themselves are not renamed or moved from the tree, and a name already taken in the target folder is refused.

Order, colours and pins

The ⋯ button of the panel sorts the folders: Order opened (the default), Name A → Z, Name Z → A or Recently modified first. Pinned folders (📌) always stay on top, in the order you pinned them. Colours: Tones of the theme colour (the default: shades of the colour chosen in View → Theme…), Multicolour (a different hue for each folder) or No colour; a single folder can get its own colour from its right-click menu.

Dedicated instances

Some files or folders deserve a Vigía of their own — a to-do list, a wiki — so they never get mixed with your other work. Right-click a file, or the title of a folder, and choose Open in a dedicated instance, or Desktop shortcut (dedicated instance) to get a shortcut that always opens it that way. A dedicated instance is a separate window with its own settings, open folders, recent files and size; its name is shown in the title bar. Opening it again brings that window to the front instead of starting another one. It starts with the language, theme and colour of the main window. (Technically: Vigia.exe --profile "Name" "path"; its settings live in %APPDATA%\Vigia\profiles\Name.)

Inside a dedicated instance, File → New window and Open in a new window in the Files panel open another window of that same instance; in the main Vigía they open an extra window of the main one. An extra window can be used freely: it never writes over the first window's open folders or size.

What opens when Vigía starts

Choose it in File → Folders at start or in the ⋯ button of the panel:

OptionWhat happens
Reopen the folders of the last sessionThe panel comes back exactly as you left it (the default).
Start clean, with no foldersEvery start begins with an empty panel.
Start clean, only with the pinned foldersEvery start shows just the folders you pinned — for example the one or two projects you always work on.

The documents are a choice of their own: File → Reopen tabs at start opens again the files of the tabs you had (see Tabs).

The panel follows the disk: files and folders created, renamed or deleted by other programs (for example in Explorer) appear or disappear at once, and the tree stays where you left it (saving a file does not rebuild it). If a whole open folder is deleted, or a network drive goes away, its block stays with the note not available and comes back by itself when the folder does; clicking a file that was deleted meanwhile just refreshes the panel. Hidden folders and tool folders (.git, node_modules, bin, obj…) are left out. Recent folders are listed in File → Open recent.

8. Files

ActionHow
OpenFile → Open (Ctrl+O), double-click a .md file, or drag a file onto the window. Each one opens in a tab of its own.

Save / Save asCtrl+S / Ctrl+Shift+S. New files are saved as UTF-8 without BOM, the same as GitHub; existing files keep their encoding and line endings.

Autosave is on by default: a file with a name saves itself a moment after you stop typing, and closing its tab saves without asking. The Autosave switch in the toolbar (also File → Autosave) turns it off; then only Save writes the file, and if you close a document with unsaved changes, Vigía asks whether to save them. Autosave never writes over a change made by another program: Vigía asks first. A new document is saved by itself once it has a name.

Images and links

Relative paths work as on GitHub: ![diagram](img/diagram.png) shows the image stored next to the .md file. In GitHub preview, links to web pages open in your browser, links to other .md files open in Vigía, and #heading links jump inside the document.

9. Export and print

Export to HTML saves a single, self-contained HTML page with the GitHub style embedded — ready to e-mail or publish. The pictures of the document that are on this computer go inside the page, so it shows them anywhere; pictures from the web keep their address.

Print / PDF (Ctrl+P) prints the GitHub-style page. Choose Save as PDF as the printer to create a PDF.

10. Working tools

FeatureHow it works
Find / ReplaceCtrl+F / Ctrl+H open a bar above the document. F3 and Shift+F3 jump between matches; Esc closes it. Aa matches case.
OutlineCtrl+Shift+O or the outline button of the toolbar shows the headings in the sidebar, below the files; click one to jump to it. With the Files panel hidden, the outline fills the sidebar. The layout button, View → Layout or dragging its title (CONTENTS) puts it beside the files, above them, or on either side of the text.
Your formatting is keptOnly what you change is rewritten when you save, down to the part of a line you touched: list markers, __bold__, _italics_, tags such as <kbd>, table alignment, line endings (CRLF/LF) and BOM stay as they were.
Changed outsideIf another program modifies the open file, Vigía reloads it (or asks first if you have unsaved changes) and marks what changed in green for a few seconds: new or rewritten paragraphs, and only the point or row added to a list or a table.
Reading at the endIf you are at the end of a view when another program adds text at the bottom, the view goes down with it. Anywhere else you stay where you were.
Text widthView → Text width: Normal (980 px, as on GitHub), Wide (1280 px), Very wide (1600 px) or The whole window, for the Visual and GitHub views. The choice is remembered per profile; printing and exported pages keep GitHub's width.
PicturesBeside the document or in another folder (../img/a.png). In the GitHub view also by an absolute path (C:\Pics\a.png, or \\server\share\a.png when that network folder is the document's folder or one open in the panel; other network pictures are blocked, so a downloaded file cannot make Windows send your credentials to a server) or a file: address, with spaces in the path, and as ![[picture.png]] or ![[picture.png|300]], looked for in the open folders; ![alt|300](a.png) sets the width. A picture that is not found shows its name in a dashed box; a click on a picture opens it in its viewer.
TablesA long path, address or piece of code in a cell breaks where it has to, so the table fits the column instead of hiding behind a scrollbar; plain words stay whole. A table of eight columns or more takes less padding.
Properties at the topA block between two --- lines at the start of a file (front matter, as GitHub, Jekyll or Obsidian use) is shown as properties, not as text: in the Visual view a grey box folded to its first lines, which opens while the cursor is in it; in the GitHub view a table under a Properties line, closed until clicked. The block is saved exactly as it was written.
[[name]] linksIn the GitHub view, [[name]] (also [[name|text]] and [[name#heading]]) links to the Markdown file of that name in the open folders, as in a wiki; the nearest one wins. A name that matches no file is shown in red. The text of the file does not change.
Crash recoveryUnsaved work is backed up every 20 seconds (each tab on its own). If Vigía or Windows stops unexpectedly, the next start offers to recover it. Files are written in one step (a temporary file next to them takes their place), so a power cut in the middle of a save leaves the old version or the new one, never an empty file. An unexpected error is written to error.log in the settings folder and the drafts of every tab are saved.
Spell checkOn by default, with English, Spanish and Japanese at once: a word is right when any of those languages knows it, so a text that mixes languages is checked as a whole. Words no chosen language knows get a red wavy line, in the Visual and Markdown views; code (code blocks, `inline code`) and addresses are never checked. View → Spell check turns it on or off for every open tab (nothing typed is lost). Right-click a marked word: the suggestions come first (a click replaces the word), then Ignore (until Vigía closes), which stops marking that word in every tab until you close Vigía, and Add to dictionary, which accepts it from then on (it is kept in this profile's settings). View → Spell check languages and dictionary… (also at the end of that right-click menu) turns the checking on or off, picks the languages (tick several), lists the words added to the dictionary so you can select them and Remove them, and Add a language… takes any Hunspell dictionary (a .dic file with its .aff next to it, as LibreOffice and Firefox use) for another language. Vigía brings its own English and Spanish dictionaries, so nothing has to be installed in Windows; Spanish comes twice, the general one and the Spanish of Uruguay, which knows the voseo (tenés, mirá), and both are on by default. There is no Japanese spelling dictionary (no program checks Japanese spelling): Japanese text is never marked, and the English or Spanish words inside it are checked.
One window per fileOpening a .md while Vigía is running brings the existing window forward, with the file in a tab, instead of starting a second copy. File → New window still opens another one.
UpdatesVigía checks once a day for a new version (once for all the dedicated instances); Help → Check for updates does it on demand. When there is one, a single question — Update now, What's new or Later — and the rest happens by itself: the release's checksums must carry the author's digital signature, and the installer is downloaded and checked against them (a release without a valid signature, or an installer that does not match, is refused and never run), every Vigía window closes (saving first, or asking if it cannot), the new version installs in silence with the same options, and the windows open again, each with its profile, its files and its tabs. If a window is not closed (its question answered with Cancel), nothing is installed and the others come back.
Markdown guideHelp → Markdown guide (GitHub) opens GitHub's own guide to the Markdown syntax in your browser, in the language of the menus.
AboutHelp → About Vigía shows the version, author, license and credits. Copy info copies the version details, handy for reporting a problem.
Sample documentA sample that shows every feature in the three views. It opens on the first start and from Help → Sample document, and it is pinned at the top of File → Open recent; Hide sample, right below it, removes it from that list, and Help → Show sample in Open recent brings it back. It opens as an untitled copy, so the original is never overwritten, and it changes language together with the menus.

GitHub extras

Also rendered exactly like GitHub: alerts (> [!NOTE], [!TIP], [!IMPORTANT], [!WARNING], [!CAUTION]), ```mermaid diagrams, math ($E=mc^2$ and $$ … $$), footnotes ([^1]) and emoji shortcodes (:rocket:).

11. Language, theme and zoom

Language menu: English, Español or 日本語. It changes the menus, the toolbar tooltips and dialogs immediately. The first time, Vigía follows the Windows language.

View → Theme… opens the theme window. Appearance: Light, Dark or Automatic, which follows Windows (Settings → Personalisation → Colours) and switches by itself when Windows does. Colour: a catalogue of twelve colours for the icon and the highlights. The chosen colour becomes the background of the icon everywhere — window, taskbar, desktop and Start-menu shortcuts, .md files — and colours the folders of the Files panel, the check marks and the selected item. The default is sky blue. Shortcuts you made with an icon of your own are not changed.

Zoom with the zoom bar at the right of the status bar (−, slider, +; click the percentage to go back to 100 %), Ctrl + mouse wheel, Ctrl++, Ctrl+- and Ctrl+0. Language, theme, mode and zoom are remembered, and the window opens again with the size, place and maximized state it had when it was closed (centred if that place is no longer on a screen).

14. Troubleshooting

What happensWhat to do
At start: Microsoft Edge WebView2 Runtime is requiredVigía draws its pages with WebView2, part of Windows 11 and of an up-to-date Windows 10. Install the Evergreen runtime from https://go.microsoft.com/fwlink/p/?LinkId=2124703 and start Vigía again.
The setup does not run on this PCVigía is built for Windows 10/11 on x64 (64-bit Intel or AMD) only; there is no build for ARM processors.
Windows SmartScreen warns about the setupIf you downloaded it from the project's Releases page, choose More info → Run anyway. Never run a copy of unknown origin.
The formatting buttons are greyThey work in the Visual and Markdown views with Edit chosen. In the GitHub view, or in Read only, they are greyed out on purpose: press Ctrl+1 and Ctrl+Shift+L.
Typing does nothingThe document is in Read only; the status bar says so. Choose Edit in the toolbar or press Ctrl+Shift+L.
New Markdown file, New folder or Delete are greyThe tree is locked. Click the padlock at the top of the Files panel; click it again when you are done.
… was changed by another program. Reload it and lose your unsaved changes?Another program wrote the file while you had unsaved changes. Reload shows its version (yours is lost); Keep my changes leaves your text, and the next save writes it over the other version.
A folder of the panel says not availableThe folder was deleted or renamed, or its network drive or USB stick is not there. The block comes back by itself when the folder does; close it from its right-click menu if it is gone for good.
A picture shows only its name in a dashed boxThe file is not where the link says. Pictures on another computer (\\server\share) show only when that folder is the document's or one open in the Files panel: open it in the panel.
A link opens Explorer instead of the fileOn purpose: links open only web pages, e-mail, Markdown files, pictures and PDFs. Any other file is shown in Explorer, never run.
Japanese words are never underlinedThere is no Japanese spelling dictionary; the English and Spanish words in a Japanese text are checked. Marks show in the Visual and Markdown views, not in the GitHub view.
Vigía closed unexpectedlyStart it again: it offers to recover each unsaved document. The error is written to error.log in the settings folder; Help → About Vigía → Copy info copies the version details for a report.
An update was refusedIf the signature or the checksum of the downloaded installer does not match, nothing is installed and the installer is deleted: try again later, or install from the Releases page. Another Vigía window did not close: close it (or answer its question) and check again.
Could not check for updatesThe check needs to reach github.com. Try again when the connection works; Vigía also checks by itself once a day.
Open with Vigía is missing from a folder's right-click menuIn Windows 11 it is under Show more options. If it is not there either, run the setup again and tick Add "Open with Vigía" to folders in Explorer.
The settings look wrongA damaged settings.json is replaced by its previous save (settings.json.bak) by itself. To start from scratch, close every Vigía window and rename the folder %APPDATA%\Vigia; a dedicated instance has its own in profiles.
